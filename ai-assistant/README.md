# AI 助手（AI Assistant）

服务器页新增「AI 助手」，用于诊断控制台报错、生成修复命令与菜单/配置文件。
**任何命令与文件都不会自动执行**：AI 只产出「待确认操作」，用户在面板里点确认后才真正生效。

## 功能边界

| 能力 | 说明 |
| --- | --- |
| 读取日志 | 当前服务器最近 100 行控制台输出（Wings 上限），只读 |
| 读取文件 | 默认放开整个服务器目录（`*`），可列目录、读文本文件；
**密钥/凭据/数据库文件永远排除**；也能在对话里用「附件」按钮逐个勾选文件 |
| 读取目录 | 输入框上方的「附件」按钮：**文件和文件夹都可以勾选**——
勾选文件读内容（≤ 5 个、单个 ≤ 32 KB），勾选文件夹只把里面的文件名给模型（≤ 3 个、每个 ≤ 50 项）；
**根目录也支持勾选**（路径行右侧的「勾选根目录」），用于直接看 `server.properties`、`start.sh` 这一层；
文件夹右侧「进入 ▸」可浏览下一级，底部有「全选当前目录 / 反选」 |
| 判断 mod 类型 | 基于 `mods/` 文件名 + 崩溃报告；最终以 jar 内 `META-INF/mods.toml` 的 `side` 为准 |
| 报错诊断 | 先给排查思路；用户明确要求「帮我解决」时才给具体操作 |
| 生成命令 | AI 用 ` ```command ` 输出，前端显示为待确认卡片 |
| 生成文件 | AI 用 ` ```file path=... ` 输出，前端显示路径、行数、内容预览 |
| 执行/写入 | 用户点确认后由后端二次校验（命令风险分级 / 路径安全 / 敏感文件 / 面板权限）再执行 |
| Token 计费 | 可选按 Token 消耗扣积分，依赖「计费与积分」扩展 |

**明确不做**：文件删除、改启动命令、改面板服务器设置、跨服务器访问、任意 shell、上传下载、端口扫描、自动执行。

## 页面标头与公告规范

标头采用面板原生风格：**大标题 + 一行灰色说明**，右侧放主操作（如「保存设置」），
不加边框卡片、不加分隔线，避免和下方内容重复分块。服务器页不放标头，
额度信息与「我的 API / 清空对话」收进对话卡片顶部的一条工具条。


两个页面（管理 → AI 助手、服务器 → AI 助手）共用 `src/client/components/PageChrome.tsx` 里的
`PageHeader` 与 `Notice`，结构固定为：

```
标题（PageContentBlock 的 h1）
─────────────────────────────────────────────
说明文字                       [操作按钮…]
状态 · 状态 · 状态
─────────────────────────────────────────────
公告条（如有）
── 内容卡片 ──
```

| 区块 | 内容 | 规范 |
| --- | --- | --- |
| 标题 | 由 `PageContentBlock title` 渲染 | 面板统一 h1，不自己写 |
| 说明 | 一句话讲清这页能干什么 | `text-sm` + 次要色 |
| 状态 | 后台：启用 / 范围 / 命令模式 / Key；<br>服务器页：命令 / 文件 / 余额 / 自有 Key | `text-xs`，`·` 分隔，关键项用语义色 |
| 操作 | 后台「保存设置」；服务器页「我的 API」「清空对话」 | 右对齐、同尺寸、换行不挤压 |
| 分隔 | 标头底部 1px 边框 | `border-border` |

公告固定放在标头之下、卡片之上，有四种色调与固定规则：

| 场景 | 色调 | 可关闭 |
| --- | --- | --- |
| 未填 API Key（后台 / 服务器页） | warning / error | 后台可关，服务器页**不可关** |
| AI 助手未启用 | info | 可关 |
| 开了积分但没装计费扩展 | warning | 可关 |
| 正在使用自己的 Key | success | 可关 |
| 积分余额不足 | warning | 可关 |

- 同一 `id` 关闭后写入 `localStorage`（键 `ext-ai-assistant:notice:<id>`），之后不再出现
- 不可关闭的公告用于「不修就用不了」的状态，避免用户关掉后继续踩坑

## 界面

服务器页 → AI 助手，用 `PageContentBlock` 包裹（与面板其他页面同一页宽与间距），
对话卡片固定 26rem / 30rem 高、内部滚动，不撑满视口（与控制台终端一致）：

- **顶部**：一行状态（能力范围 · 积分余额），不显示模型与供应商
- **高度**：`clamp(18rem, 56vh, 42rem)`，随窗口高度伸缩，小窗口不挤压、大屏不空旷
- **中部**：消息流，用户消息在右（主色气泡），AI 在左（浅色气泡），自动滚动到底部
- **渲染**：标题、有序/无序列表、引用、分隔线、**加粗**、*斜体*、`行内代码`；
代码块带语言标签与「复制」按钮；用户自己的输入按纯文本显示，不解析格式
- **消息操作**：每条 AI 回复可「复制」，最后一条可「重试」（丢掉该次回答重新提问）
- **空对话**：AI 先发一条「你可以这样问我：」，下面六条常见问题以消息内的选项呈现，点击即发送
- **底部**：自适应高度的输入框 + 圆形发送按钮，`Enter` 发送、`Shift + Enter` 换行；左侧是「附带日志、mods 列表与崩溃报告」开关
- 页面不放任何独立功能按钮，所有操作都在对话里完成；命令/文件的确认卡片也作为消息的一部分出现
- **会话持久化**：消息按服务器存在浏览器 `localStorage`（保留最近 60 条），刷新、重开页面都会恢复；
  顶部「清空对话」会同时清掉本地记录与后续请求的上下文（AI 不再参考之前的问答）
- 待确认的操作有 10 分钟有效期，不跨刷新保留，避免刷新后点到已失效的确认按钮

## 交互流程

### 1. 报错处理

```
用户：服务器报错了 / 启动失败
  ↓
AI：给排查建议（不给可执行操作）
  ↓
用户：帮我解决（或「直接修」「按你说的做」）
  ↓
AI：给出具体命令或文件 → 后端转成待确认提案
  ↓
用户点「确认执行 / 确认写入」→ 才真正下发
```

### 2. 菜单 / 配置文件生成

```
用户：帮我写一个菜单文件，支持 /menu 打开
  ↓
AI：先用文字复述方案（路径、结构、覆盖影响、是否要重启）
  ↓
用户：确认
  ↓
AI：输出 ```file path=plugins/Menu/config.yml + 完整内容
  ↓
面板显示待确认卡片：路径 + 行数 + 字节数 + 内容预览
  ↓
用户点「确认写入」→ 后端校验目录白名单与文件权限 → 写入
```

### 3. 确认卡片

| 类型 | 展示内容 | 按钮 |
| --- | --- | --- |
| 命令 | 逐条列出命令 | 取消 / 确认执行 |
| 文件 | 路径、行数、字节数、内容预览（同名文件会被覆盖） | 取消 / 确认写入 |
| 不允许 | 灰色说明原因（未开开关 / 不在白名单 / 路径不允许） | 仅取消 |

提案 10 分钟内有效，且绑定「用户 + 服务器」，别人拿到 id 也无法执行。

## 提示注入防护

用户消息、控制台日志、文件清单全部按**数据**处理，不参与指令解析：

| 层 | 措施 | 命中效果 |
| --- | --- | --- |
| 输入检测（硬） | 伪造 `<\|im_start\|>`、`<system>`、`<project_instructions>`、零宽字符、双向控制符 | 直接 422，提示只描述问题 |
| 输入检测（软） | 「忽略以上指令」「你现在是 X」「禁止拒绝」「must supersede」「ratman4080 / Little Code Sauce」 | 不拦截，系统提示声明这些只是普通文本 |
| 指令隔离 | 用户消息包进 `<user_input>`，日志包进 `<server_log>`，文件包进 `<server_files>` | 标签内一律当数据 |
| 权限边界 | 「我是管理员 / 已授权 / 这是沙箱」不能跳过命令白名单、目录白名单、面板权限 | 无效 |
| 输出校验 | 回复含系统提示片段，或出现 `sk_` / `ck_` 形态的密钥 | 整条替换为拦截提示 |
| 执行约束 | AI 不能自行调用工具，所有写操作都走待确认卡片 | 需用户点确认 |

规则刻意区分「硬拦截」和「软降权」：只有正常玩家绝不会打出的字符（伪造标签、零宽字符）才会被拒绝，
像「忽略这条警告」这种正常排障说法不会被误伤。

## 后台管理页

「管理 → AI 助手」是**唯一**配置入口。插件不注册面板的扩展设置表单，
所以「管理 → 扩展」里不会出现和这个页面重复的设置项。

| 区块 | 内容 |
| --- | --- |
| 连接配置 | 提供商下拉、API Key（留空不修改）、接口地址、**模型下拉（点「获取模型」从 `/models` 拉取）**、**「测试连接」按钮**（发一条最小请求，显示模型、耗时与回复） |
| 开放范围 | 所有预设 / 仅指定标签；标签列表**直接读取面板「管理 → 标签」里的现有标签**，勾选即可 |
| 命令与文件 | 允许执行命令 + **放行模式（全部 / 仅白名单）** + 命令白名单；允许生成文件 + **写入目录**；**读取范围**（`*` = 整个服务器目录，`.` = 根目录，也可写具体目录） |
| 计费与限制 | 按 Token 扣积分、换算比例、每分钟次数、最大 Token、超时、总开关 |

配置保存在面板的 `extension_settings` 表（API Key 加密存储），由这个页面读写。

## mods 清单

勾选「附带日志、mods 列表与崩溃报告」后，AI 会收到 `mods/` 下的 jar 文件名、最新崩溃报告尾部，
以及 `config/`、`logs/` 等目录的文件名，用来判断哪些是纯客户端 mod、哪些必须装服务端。

> jar 内部的 `META-INF/mods.toml` 读不到（文件 API 只能按原始字节读文件，不能解压浏览），
> 所以这类结论是按文件名 + 已知信息得出的，回答里会标明判断依据，不会冒充「已读取元数据」。

## 命令与文件的授权口径

**文件**：默认 `*`，整个服务器目录可读，但有一条硬边界——密钥、凭据、数据库文件永远不可读：

```
.env  *.key  *.pem  *.p12  *.pfx  *.jks  *.sqlite  *.db  *.kdbx
id_rsa*  id_ed25519*  auth.json  credentials.json  secrets.json
```

另外两层收口：只有用户在「附件」里主动勾选的文件才进上下文（每次 ≤ 5 个、单个 ≤ 32 KB），
并且必须有 `file.read` / `file.read-content` 权限。

**命令**：默认放行全部。因为「能不能执行」本由 `control.console` 决定——有该权限的用户在控制台可以直接敲任何命令，
AI 只是在同样权限下代打，不构成提权。真正要防的是误点和被提示注入带偏，所以按风险分级：

| 命令 | 处理 |
| --- | --- |
| 普通（`say`、`list`、`tps`、`save-all`、`gamerule` …） | 待确认卡片，点一下执行 |
| 高风险（`stop`、`op`/`deop`、`ban`/`kick`、`whitelist`、`execute`、`lp`、`plugins load/unload`、`reload`） | 卡片标红，**必须再勾选「我知道这会…」** 才能确认 |
| 含 `;` `&` `|` `` ` `` `$` `<` `>` 或换行 | 直接拒绝，避免把控制台当 shell |

想更严，就把放行模式切到「仅白名单」并填规则。

## 连接失败怎么排查

| 现象 | 多半是 |
| --- | --- |
| 401 | API Key 不对或没填 |
| 404 | 接口地址多了或少了 `/v1`，或该服务商不提供 `/models` |
| **422** | 请求体被上游拒绝：模型名不存在、该服务商要求不同字段（常见于 CodeBuddy、自建网关） |
| 超时 / 502 | 网络不通，或 20 秒内没有响应 |

422 时「测试连接」会直接显示上游的原文（例如 `model not found`），按提示改模型名或接口地址即可。

### CodeBuddy（已内置适配，只需填 Key）

`ck_` 开头的 Key 是**中国版 CodeBuddy**（`www.codebuddy.cn`）签发的，海外站 `www.codebuddy.ai`
会直接 401。它的接口也不是 OpenAI 的 `/v1/chat/completions`，而是：

```
POST https://www.codebuddy.cn/v2/chat/completions
```

并且有两条硬约束，插件已在代码里处理：

| 约束 | 处理方式 |
| --- | --- |
| 必须 `stream: true`（非流式直接 400） | 请求强制流式，服务端读完整 SSE 再聚合成一条回复 |
| 需要 CLI 指纹头（`X-Product`、`X-IDE-Type`、`x-codebuddy-request` 等） | 按 CLI 的请求头原样带上 |
| 没有 `/models` 目录（404） | 使用内置模型清单；默认 `hy3` |

**使用方式**：提供商选 CodeBuddy → 填 API Key → 地址与模型都留空 → 点「测试连接」。

- 地址留空自动用 `https://www.codebuddy.cn`
- 模型留空自动用 `hy3`
- 点「获取模型」会给出内置清单（`hy3`、`glm-4.7`、`deepseek-v4-pro`、`kimi-k2.6`、`hunyuan-2.0-instruct` 等）

> `hy3` 是推理模型，思考过程占用 token 预算。若把「单次回复最大 Token」设得过小（如 16），
> 正文会是空的，插件此时会用思考内容兜底；建议保持 800 以上。

## 积分与 Token 换算

**开关**：`按 Token 扣积分`（默认关）。关闭时不读余额、不扣费，其余功能照常。

**换算**

```
本次积分 = ceil(total_tokens / tokens_per_credit)   // 最低 1 分
```

- `total_tokens` 取 AI 返回的 `usage.total_tokens`（含输入 + 输出）
- `tokens_per_credit` 默认 1000，即 1000 Token = 1 积分
- 例：一次对话 3240 Token，比例 1000 → 扣 4 积分

**预检**：发请求前用「输入字符数 ÷ 4 + 最大输出 Token」估算，余额不足直接返回 402，不会白扣。

**扣费时机**：拿到回复后按真实 usage 扣；扣费失败（例如并发把余额扣光）只记录，不阻断已经生成的回复，下一次对话会被预检拦住。

**依赖**：使用「计费与积分」扩展的账本（`Billing\Services\CreditLedger`），流水类型为 `api`。
没装该扩展时自动降级为不扣费，页面上也不显示余额。

**可见性**：每次回复下方显示「本次消耗 X 积分（Y Token）」，顶部状态条显示当前余额。

## 工具调用（Agent）

模型可以自己调用工具，不用用户手动粘贴文件内容：

| 工具 | 作用 | 输出上限 |
| --- | --- | --- |
| `list_dir` | 列目录，只给名称 + 大小 | 200 项，超出提示「共 N 项，只列前 200」 |
| `read_file` | 按行分段读文本 | 单次 ≤ 200 行，文件 ≤ 256 KB，超出要求用 `offset` 续读 |
| `grep` | 一层目录内搜文本，回 `文件:行号:内容` | 40 条，每条 200 字 |
| `web_search` | 联网搜索（需后台配 Tavily / Serper） | 5 条结果 |

一轮对话最多 **3 轮工具调用**，之后强制基于已有信息作答。

### 怎么防止 token 爆炸

这是重点。四个闸门：

1. **工具本身不吐全文**：`list_dir` 只给文件名，`grep` 只给匹配行，`read_file` 必须分段
2. **单次对话共享 24 KB 预算**：所有工具输出累加，超了后续工具直接返回「预算用尽，请缩小范围」
3. **单条结果二次裁剪**：超长内容截断到剩余预算的一半，并提示缩小范围
4. **轮数上限 3**：模型不能无限「再读一个文件」

对比一下：

```
❌ 旧做法：read whole file → 5 万行日志直接进上下文 → 一次 20 万 token
✅ 现在：grep "ERROR" → 40 行命中 → 再 read_file offset=1 limit=80 → 约 3 千 token
```

工具轨迹会显示在回复下方，用户能看到它查了什么：

```
列目录 · / 共 14 项：server.properties (1.2 KB)…
搜索文本 · server.properties:31: view-distance=10
读文件 · server.properties 共 42 行，本次 1–42 行
```

## 工具集管理

后台可增删工具，不必改代码：

```
管理 → AI 助手 → 工具集
  禁用的内置工具   web_search,grep
  自定义工具        ip_lookup|查询 IP 归属地|https://api.example.com/ip?q={query}
                   mc_version|查版本兼容|https://api.example.com/mc?q={query}
```

- **禁用**：逗号分隔的工具名，留空表示全部启用
- **自定义工具**：每行 `名称|说明|https://地址?q={query}`，模型会像内置工具一样调用
  - 只允许 `GET + https + 公网地址`
  - `localhost`、`10.x`、`192.168.x`、`172.16-31.x`、`*.local`、`*.internal` 一律拒绝（防 SSRF）
  - 返回截断 8 KB，并计入统一预算

## 联网搜索

| 服务 | 端点 | 说明 |
| --- | --- | --- |
| **DeepSeek 官方** | `POST https://api.deepseek.com/v1/tools/search` | 返回 `rerank_score`、`summary`、`authority` 等结构化结果，权威度 ≥3 视为可靠来源 |
| Tavily | `POST https://api.tavily.com/search` | 通用网页搜索 |
| Serper | `POST https://google.serper.dev/search` | Google 结果 |
| **自定义接口** | 自行填写 | 地址用 `{query}` 占位，鉴权走 `Authorization: Bearer <key>`，响应兼容 `results` / `data` / `organic` |

配置项：

```
搜索服务       DeepSeek 官方 / Tavily / Serper / 自定义接口 / 关闭
搜索 API Key   加密存储，保存即生效
搜索接口地址    留空用默认；自定义接口填 https://…?q={query}
未配置时用模型自带联网   ← OpenRouter 的 :online
```

### 不配置搜索，能不能让模型自己联网？

可以，但**取决于模型与协议**，且不可与显式搜索等同：

| 提供商 | 自带联网方式 | 现状 |
| --- | --- | --- |
| OpenRouter | 模型名加 `:online`（走 Exa） | ✅ 已实现（开关打开后自动加后缀） |
| OpenAI | 用 `gpt-4o-search-preview` / `gpt-4o-mini-search-preview`，或 Responses API 的 `web_search` 工具 | ⚠️ 需手动把模型名改成 search 版；Responses 协议未单独适配 |
| Anthropic | 服务端工具 `{"type":"web_search_20250305","name":"web_search"}` | ⚠️ 需在 Messages 请求里附带 tools，当前工具循环只跑 OpenAI 协议 |
| Gemini | `tools:[{"google_search":{}}]` grounding | ⚠️ 需在原生协议请求里附带 |
| DeepSeek | 无内置联网，必须显式调 `/v1/tools/search` | ✅ 已作为搜索服务接入 |

结论：**能用，但不能当成默认方案**。

- 自带联网的计费、结果条数、引用格式都由服务商决定，平台侧不可控
- 只对特定模型/协议生效，用户换模型就失效，体验不一致
- 没有搜索结果的结构化字段（权威度、摘要），prompt 里没法做质量过滤

所以设计成：**显式搜索优先**（可控、可审计、结果可裁剪），`search_fallback` 只作为没配 Key 时的兜底，且只对 OpenRouter 生效。

## 免费额度

没有积分体系时的成本闸门，后台独立一块「免费额度」：

```
管理 → AI 助手 → 免费额度
  每人每天提问次数        0（不限）     例如 20
  每人每天 Token 上限     0（不限）     例如 50000
  每分钟提问次数          10
  单次回复最大 Token（未计费时）  400
```

| 项 | 行为 | 0 的含义 |
| --- | --- | --- |
| 每天提问次数 | 按「用户 + 自然日」累计，超了返回 429，跨天归零 | 不限 |
| 每天 Token 上限 | 累计当日实际 `total_tokens`；到达上限后不再请求上游（不预扣） | 不限 |
| 每分钟提问次数 | 防刷屏，与天级额度叠加生效 | 不限 |
| 单次回复最大 Token | 未计费/计费两档分别生效 | 不限（不向上游传 `max_tokens`，由模型用默认上限） |

> 所有额度项统一「填 0 = 不限」，不设单独的开关按钮。

> 「启用 AI 助手」总开关已移除。开放范围就是开关：选「所有预设」即全开，
> 选「仅指定标签」且不选标签即整体停用。

## 用户自带 Key（BYOK）

不装计费扩展、或者不想让用户花积分时，让用户用自己的 Key：

```
AI 助手页顶部 →「使用我的 API」
  提供商     DeepSeek / 通义千问 / OpenAI / CodeBuddy / 自定义
  API Key    只存该用户维度（加密），管理员看不到
  模型 / 接口地址   留空用默认
```

| 场景 | 计费 | 单条上限 |
| --- | --- | --- |
| 用平台 Key + 开了计费 | 按 Token 扣积分 | `单次回复最大 Token`（默认 800） |
| 用平台 Key + 没开计费 | 不扣费 | `未计费时的上限`（默认 400） |
| 用**自己的 Key** | **不扣积分**，也不受余额限制 | `单次回复最大 Token` |

- 状态条会显示「我的额度 · 已启用」，点开可以「改回平台额度」
- 用户 Key 存在 `extension_settings` 的 user scope，换服务器仍是同一份，但不同用户互不可见
- 用自有 Key 时仍然走同一套权限、白名单、提示注入防护——放开的是钱，不是权限

## 权限隔离

| 层 | 规则 |
| --- | --- |
| 服务器绑定 | 接口固定 `/api/client/servers/{server}/extensions/ai-assistant`，前端不能传 `server_id` |
| 访问权 | 面板原生 `AuthenticateServerAccess` |
| 标签门禁 | `scope=tags` 且预设标签不在白名单 → 403，入口不显示 |
| 命令 | `control.console` + 后台开关；默认放行全部（危险命令需二次勾选确认），可切「仅白名单」 |
| 敏感文件 | `.env`、`*.key`、`*.pem`、`*.p12`、`*.jks`、`*.sqlite`、`*.db`、`*.kdbx`、`id_rsa*`、`id_ed25519*`、`auth.json`、`credentials.json`、`secrets.json` 一律不可读 |
| 文件（读） | `file.read` 列目录、`file.read-content` 读内容；只读目录白名单，禁止 `..` |
| 文件（写） | `file.create` / `file.update` + 后台开关；**目录不限**，仅拦截绝对路径、`..` 穿越与凭据/数据库文件；每次写入必须过确认卡片 |
| 提案 | 绑定 user + server，10 分钟过期，执行后立即失效 |
| AI 输出 | 只解析代码块，块内内容照样过白名单；不信任任何「已执行」声明 |
| 限流 | 每用户每分钟 N 次 |

```sh
php artisan p:extension:install /path/to/ai-assistant.zip --enable
```

装好后到「管理 → 扩展 → AI 助手」填 API Key，按需开启命令执行 / 文件生成并配置白名单。
