# 连续端口（Contiguous Ports）

把 1.0 分支 `NetworkContainer` 的「连续端口」交互搬到 2.0：**直接用「连续端口数 + 创建新的网络设置」
替换原生「新建分配」按钮**，不新增按钮、不与原生按钮并存。

## 替换范围

| 项 | 说明 |
| --- | --- |
| 位置 | 服务器 → 网络，右侧原来「新建分配」按钮的位置 |
| 原生按钮 | 被隐藏（`display: none`），由本扩展的控件取代 |
| 新控件 | `连续端口数:` + 数字输入框 + `创建新的网络设置` 按钮 |
| 不受影响 | 端口表格、设为首选、删除分配、备注、额度提示文字 |

额度为 0 或已用完时，不显示创建入口（与 1.0 一致，1.0 在这种情况下同样不渲染按钮）。

## 与 1.0 的行为对照

| 1.0 分支 | 本扩展 |
| --- | --- |
| `consecutiveCount` 默认 1 | 相同，默认 1 |
| 输入范围 `[1, min(consecutiveLimit, 剩余额度)]` | 相同，`consecutiveLimit` 由后台「单次最多分配数量」提供（默认 16，上限 64） |
| 输入变化时 clamp：`Math.max(1, Math.min(limit, parseInt(v) || 1))` | 相同 |
| 点击时 `count = count > 1 ? count : undefined` | 相同：`> 1` 走连续分配，`1` 走原生随机分配 |
| `POST /network/allocations`，body `count > 1 ? { count } : {}` | 数量 1：调原生接口（随机一个）；数量 > 1：调扩展接口按端口号连续分配 |
| 成功后把新分配并入列表 | 成功后 `invalidateQueries()`，端口表格即时刷新 |
| 每行显示 `你正在使用 X / Y 个允许的网络设置。` | 沿用 2.0 原生提示（`此服务器已使用 X / Y 个允许的分配。`） |

### 额度口径（与 1.0 一致）

`allocation_limit` 是**分配总数**的上限，主分配也算一个，所以：

```
剩余可创建 = allocation_limit - 当前分配总数
```

例如 `allocation_limit = 5`，已有 1 个主分配 + 1 个额外端口（共 2 个）：

- 还能创建 **3** 个
- 输入 4 会被后端直接拒绝，并提示「当前已有 2 个，最多还能创建 3 个」
- 输入框的上限同样按 3 计算，不会让前端先放行、后端再报错

前后端共用这一个口径，不会出现「只剩 1 个额度却创建了 2 个」的情况。

## 分配规则（数量 > 1 时）

- IP 固定为服务器主分配所在的 IP
- 在同节点、同 IP、未分配给任何服务器的端口里，按端口号升序找第一段连续空闲端口
- 段长不足时整体拒绝，不会只分配一部分
- 写入后调用 `Daemon::server($server)->sync()`，无需重启

## 权限

沿用面板服务器 API 鉴权，并要求当前用户拥有该服务器的 **Allocation Create**（`allocation.create`）。
子用户没有该权限时，创建按钮调用会返回 403。

## 后台设置

| 设置项 | 默认 | 说明 |
| --- | --- | --- |
| 单次最多分配数量 | 16 | 即 1.0 的 `consecutiveLimit`，最大 64 |

## 安装

```sh
php artisan p:extension:install /path/to/contiguous-ports.zip --enable
```
